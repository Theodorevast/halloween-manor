# Halloween Manor：万圣节鬼屋设计

> 日期：2026年10月26日
> 状态：第 1 段（体验与玩法）已由用户确认；其余各段是用户离开期间按推荐项写的，见文末「替用户做的决定」
> 工作标题：Halloween Manor（可改）

## 目标与约束

玩家扮演一只鬼，从斜俯视的上帝视角看着一栋黑暗的鬼屋。AI 控制的访客拿着手电筒在屋里走动，玩家附身屋里的物件去吓他们，把他们吓得尖叫着逃出门。沙盒玩法，没有输赢。

| 约束 | 内容 |
|---|---|
| 截止 | 2026年10月31日 必须是成品，吉祥物模型也要换上 |
| 分享方式 | 公开网址，任何人点链接就能玩；配置一般的电脑也要流畅 |
| 界面语言 | 英文 |
| 平台 | 桌面浏览器优先；手机上能点、不崩即可，不做手机专属功能 |
| 角色 | Tripo 吉祥物（用户 2026年10月27日 前提供 GLB）；在此之前用占位模型 |
| 许可 | 公开部署：不用 AGPL、GPL、专有许可的库（沿用 `工具/13-网页交互.md` 的许可红灯清单） |
| 声音 | 沿用 `工具/04-程序化合成.md` 的风格规则：不用大调、和弦进行、上行音阶、「叮」类奖励音 |

## 1. 体验与玩法（已确认）

### 开场

黑屏，写着「Put on headphones. Click to begin the haunting.」。这一下点击解锁 `AudioContext`，镜头缓缓降到鬼屋上方，2 秒后第一个访客推门进来。

### 鬼屋

一层，16 × 12 米，按 0.5 米一格划成 32 × 24 的格子（精确布局见 `src/config/house.ts`）。6 个房间各约 4.5–5 米宽、4 米深，由一条 2 米宽的东西向走廊连通，前门在门厅南墙，是访客唯一的出入口。

```
x→ 0          5           10.5       16
z  ┌──────────┬───────────┬──────────┐ 0
↓  │ Study    │ Living    │ Kitchen  │
   │          │           │          │
   ├──  ──────┼────  ─────┼───══─────┤ 4.5   ══ 厨房门（可附身）
   │               Hall              │
   ├──  ──────┼────  ─────┼────  ────┤ 7
   │ Bedroom  │ Foyer     │ Bathroom │
   │          │           │          │
   └──────────┴───[前门]──┴──────────┘ 12
```

屋里是黑的，只有窗户透进暗蓝色的月光。

### 镜头

正交相机斜俯视（方位角 45° + k × 90°，仰角约 35°）。Q / E 键或屏幕按钮按 90° 旋转，过渡 0.45 秒缓动；滚轮在 0.75–1.6 倍之间缩放；不做平移，整栋房子始终在画面内。

### 可附身物件

物件分两类：**引诱**（发出声音，把听见的人引过来查看）和**惊吓**（必须被人看见才生效）。核心策略是先引诱、再惊吓。

| 物件 | 位置 | 类型 | 作用距离 | 恐惧值 | 冷却 | 表现 |
|---|---|---|---|---|---|---|
| Music box（八音盒） | 卧室 | 引诱 | 7 m | 4 | 14 s | 走调的小调旋律，响 4 秒 |
| Door（厨房门） | 厨房与走廊之间 | 引诱 | 9 m | 10 | 10 s | 猛地关上 |
| Lamp（台灯 ×2） | 客厅、门厅 | 惊吓 | 6 m | 18 | 8 s | 闪烁 1.2 秒后熄灭，6 秒后自己亮回来 |
| Rocking chair（摇椅） | 客厅 | 惊吓 | 6 m | 22 | 10 s | 自己摇起来，越摇越快，3 秒 |
| Portrait（画架上的肖像） | 书房 | 惊吓 | 6 m | 32 | 16 s | 眼睛跟着人转，然后整幅画砸到地上；10 秒后复原 |
| Mirror（落地镜） | 浴室 | 惊吓，且要站在 2.5 m 内 | 2.5 m | 48 | 20 s | 镜子里浮现一张脸，1 秒 |

- **引诱**：触发时，作用距离内所有听得见的人（中间隔墙时距离按 0.6 倍算）恐惧值增加，并转入「警觉」状态，走到物件旁查看
- **惊吓**：触发后有 1.5 秒的生效窗口，窗口内**看见**它的每个人各被吓一次。没人看见就白白浪费这次冷却
- 物件上方显示一个小眼睛图标，表示此刻有人能看见它，玩家可以据此判断出手时机
- 所有物件都是落地摆放的（肖像放在画架上、镜子是落地镜），不挂墙，这样墙降低时它们不受影响

### 访客（NPC）

**恐惧值**：0–100，显示在头顶的恐惧条上。连续 4 秒没被吓，每秒回落 3 点。恐惧值不低于 60 时进入「紧张」：走路变快，手电光抖动。

**状态机**：

```
闲逛 ──听到声音──▶ 警觉 ──到达查看点，看 3 秒──▶ 闲逛
 │                   │
 └──被吓──▶ 受惊 ◀──被吓┘      受惊：僵住 0.8 秒 → 跳起 → 恢复原状态
                 │
          恐惧值 ≥ 100
                 ▼
               逃跑 ──到达前门──▶ 离开（计数 +1）
```

| 状态 | 行为 | 速度 |
|---|---|---|
| 闲逛 | 随机挑一个别的房间，A* 寻路走过去，到了左右照 2–4 秒 | 1.3 m/s（紧张时 1.7） |
| 警觉 | 走到声源旁，手电一直指着声源 | 1.1 m/s |
| 受惊 | 原地僵住、跳起；这次涨了 15 点以上就尖叫 | — |
| 逃跑 | 冲向前门，手电乱晃 | 3.2 m/s |

**视觉**：视野就是手电光锥，半角 30°、距离 7 m，并且在格子上做视线检测（中间有墙就看不见）。

**尖叫会传染**：尖叫声 8 m 内的人恐惧值 +5，并转入警觉，跑过来看，可以串成连环惊吓。

**习惯化**：同一个人第 n 次被同一种物件吓到，效果乘以 0.5ⁿ⁻¹。

**性格**（进门时随机抽，名牌上标出）：

| 性格 | 名牌标注 | 恐惧倍率 | 抽中概率 |
|---|---|---|---|
| Timid | scaredy-cat | ×1.5 | 30% |
| Average | — | ×1.0 | 45% |
| Brave | skeptic | ×0.6 | 25% |

名字从英文名池里随机抽（Mia、Theo、Priya、Ollie、June、Sam、Nora、Leo……），同屋不重名。

### 节奏

屋里不到 3 人时，8–15 秒后有新访客进门；开局 2 秒进第一个，之后每隔 6 秒进一个，直到 3 人。

### 爽点：吓跑的瞬间

恐惧值涨满时依次触发：模拟暂停 0.15 秒（hit-stop，渲染不停），屏幕震动，一声低沉的不协和冲击音，NPC 尖叫着冲向前门，暗角泛起一圈暗红。

### 界面（HUD，英文）

| 位置 | 内容 |
|---|---|
| 左上 | `Scared off tonight: N` |
| 左下 | 事件播报，最多 4 条，旧的淡出（`Theo jumped at the portrait`、`Mia fled screaming!`） |
| 右下 | 旋转按钮 ⟲ ⟳、静音、画质（High / Low） |
| 物件悬停 | 物件名 + 冷却圆环；可用时物件泛一层幽绿的光 |
| NPC 头顶 | 名字 · 性格标注 + 恐惧条 |

## 2. 架构

Vite + 原生 TypeScript + `three`（`three/webgpu`，不支持 WebGPU 时自动退回 WebGL2）。运行时依赖只有 `three`；开发依赖为 `vite`、`typescript`、`vitest`、`@types/three`。

### 核心原则：模拟和画面分开

- `sim/` 是纯 TypeScript，**不引用 three.js**，只处理格子坐标、状态和数字。所以能用 vitest 直接测，测试里可以快进时间
- `view/`、`audio/`、`ui/` 只读模拟状态、订阅模拟事件，不反过来改模拟
- 随机数从外部注入（带种子），测试结果可复现
- 模拟固定步长 1/60 秒；渲染每帧一次，`dt` 上限 0.1 秒，防止切回标签页时跳帧

```
 输入（点击物件）──▶ sim.trigger(objectId)
                         │
          ┌──────────────┴───────────────┐
          │ sim/（纯 TS，固定步长）         │
          │  grid · pathfind · perception │
          │  npc 状态机 · scares · spawner │
          └──────────────┬───────────────┘
                 state（只读） + events
          ┌──────────┬───┴─────┬──────────┐
          ▼          ▼         ▼          ▼
        view/      audio/     ui/      debug（?debug）
```

### 角色模型的可替换性

`config/character.ts` 里一项配置：`url`、`targetHeight`（1.1 m）、`facing`（模型正面朝向）、`clips`（片段名映射到 `idle / walk / run / scared`）。加载器用 `Box3` 量包围盒，缩放到目标身高、脚底对齐地面。

- 有动画片段：用 `AnimationMixer` 播放，按状态切换并交叉淡入淡出
- 没有片段：程序化挤压回弹（走路上下弹跳，受惊时先压扁再拉长）
- GLB 加载失败：用代码生成的备用小人（胶囊身体 + 球形头 + 两点眼睛），游戏照常运行

## 3. 画面

**风格**：低多边形、平直着色，所有物体共用一套调色板。屋子整体很暗，画面靠光撑起来。

| 元素 | 颜色 |
|---|---|
| 月光（窗外的方向光 + 很弱的半球光） | 冷蓝 `#3b4a6b` 附近 |
| 手电 | 暖白 `#ffd9a8`（外圈）· `#fff1dc`（亮芯） |
| 台灯 | 昏黄 `#ffb35c` |
| 物件可附身时的光 | 幽绿 `#7dffa8`，低饱和 |
| 吓跑时的暗角脉冲 | 暗红 |

**手电**：沿用 工具 证据板的做法，每个 NPC 两盏 `SpotLight`，外圈宽而软、投阴影，亮芯窄、不投影。

**降墙**：离镜头最远的两面外墙保持全高（2.4 m，带窗），其余墙降到 0.5 m，像一张立体平面图。镜头旋转时重新计算哪两面是「远墙」。光会从降低的墙上方漏到隔壁房间，所以每面墙另放一份全高、只投影不显示的副本（放在单独的 layer 上，只让灯的阴影相机看见）。如果 WebGPU 路径不认这个 layer 设置，就接受漏光，不影响玩法。

**后处理**：轻微泛光（手电和灯）、暗角、胶片颗粒。

**画质档位**：

| 档位 | 内容 |
|---|---|
| High | 手电阴影 1024，泛光开，像素比最高 2 |
| Low | 手电阴影 512，泛光关，像素比 1 |

默认 High。开局后测 3 秒平均帧时间，超过 22 ms 自动降到 Low；右下角可以手动切换。

## 4. 声音

全部用 Web Audio 程序化合成，不用音频文件。

**原则**：环境声压得很低，惊吓才有反差。刺耳靠不协和（小二度）和突然性，不靠音量。

| 声音 | 做法 |
|---|---|
| 环境层 | D1 / D2 正弦持续音 + 低通噪声风声，响度很低；偶尔随机来一声木头嘎吱 |
| 八音盒 | 小调、音准微微走调、带抖动（wow / flutter）的短旋律，下行 |
| 门 | 噪声爆发 + 低频撞击 + 混响尾巴 |
| 台灯 | 1.8 kHz 以上的干短电流噼啪，加 50 Hz 嗡声 |
| 摇椅 | 带通噪声的嘎吱声，周期越来越快 |
| 肖像 | 一声闷响 + 碎玻璃的高频噪声 |
| 镜子 | 反向渐强 + 小二度音簇冲击 |
| 尖叫 | 共振峰合成的卡通式短促惊叫，每个人音高不同 |
| 吓跑 | 低频锯齿音簇 + 噪声的 braam 冲击 |

- 声像跟着物件在屏幕上的横坐标走（`StereoPanner`）
- 混响用代码生成的衰减噪声做冲激响应（`ConvolverNode`）
- 主总线接压缩限幅器，防止叠加时爆音
- 计数增加时**不放**任何「叮」声

Claude 听不到声音，所有音效要用户试听后定稿（见「测试与验证」）。

## 5. 出错与降级

| 情况 | 处理 |
|---|---|
| 不支持 WebGPU | 自动退回 WebGL2 |
| 连 WebGL2 都不支持 | 显示一行说明文字：浏览器无法运行 |
| 吉祥物 GLB 加载失败 | 用备用小人，控制台警告 |
| 音频被浏览器挂起（切标签页等） | 下一次点击时 `resume()` |
| 标签页隐藏 | 模拟暂停；`dt` 上限 0.1 秒 |
| 寻路失败 | NPC 换一个目标 |
| 帧率太低 | 自动降到 Low 档 |

## 6. 测试与验证

| 层 | 怎么测 |
|---|---|
| `sim/` | vitest 单测：A* 路径、视线、感知、恐惧和习惯化、状态切换、生成节奏、冷却。注入带种子的随机数，快进时间 |
| 整体运行 | Playwright 冒烟：页面无报错、画布有非黑像素、点击开场后 10 秒内有访客、用调试接口触发惊吓后恐惧值上升；截图人工看 |
| 调试接口 | 带 `?debug` 时挂 `window.__haunt`：`state()` 输出文字版状态，`step(ms)` 快进，`trigger(id)` 触发物件 |
| 声音 | Claude 用 `OfflineAudioContext` 渲染每个音效，检查峰值和响度；**听感由用户判断**，留出两轮试听 |
| 性能 | 在 Low 档下用 Chrome 降速模拟看帧率 |

## 8. 风险

| 风险 | 应对 |
|---|---|
| 吉祥物来晚或质量不合适 | 备用小人能独立上场；归一化加载器兜住尺度和朝向 |
| 公开使用吉祥物形象需要公司批准 | 由用户确认 |
| 声音靠 Claude 盲做 | 用户两轮试听；参数集中在 `audio/sfx.ts`，好改 |
| 一般电脑跑不动 4 盏投影手电 | 画质档位、自动降档 |
| 只投影的墙在 WebGPU 路径不生效 | 接受漏光 |
